# OpenAI Build Week submission checklist

Source: [Official Rules](https://openai.devpost.com/rules). Last reviewed:
2026-07-18. This file is a working checklist, not legal advice.

## Repository and project

- [x] Project is documented in English.
- [x] Apache-2.0 repository license is present.
- [x] Third-party imagery provenance and CC-BY 4.0 attribution are recorded in
  `data/DRC_PROVENANCE.md`.
- [x] Third-party model provenance and Apache-2.0 license are recorded in
  `models/README.md`.
- [x] README explains Codex collaboration and links dated implementation
  evidence.
- [x] README provides local judge setup/testing instructions.
- [ ] Confirm that the project is eligible as new or meaningfully extended
  during the Submission Period; retain dated Codex logs and commit history.
- [ ] Verify the required GPT-5.6 use and ensure the README/Devpost wording is
  supported by the actual session evidence.
- [ ] Make the repository public with its license **or** share the private
  repository with `testing@devpost.com` and `build-week-event@openai.com`.
- [ ] Add the final repository URL to Devpost.

## Devpost form

- [ ] Save **Work & Productivity** as the selected category. It was selected in
  the Additional info form on 2026-07-18, but the form was not saved because
  required personal/submission fields remain incomplete.
- [x] Save the English project description from `SUBMISSION_DRAFT.md` to
  Project details (saved 2026-07-18).
- [ ] Provide the `/feedback` Codex Session ID for the thread where core
  functionality was built. Do not substitute a guessed ID.
- [ ] Provide the required code-repository URL. If the repository is private,
  share it with `testing@devpost.com` and `build-week-event@openai.com` before
  submitting.
- [ ] Select the correct submitter type and country of residence, then save
  Additional info.
- [ ] Confirm all entrant/team-representative and eligibility details directly
  in Devpost; ensure every invited teammate has accepted.

## Public demo video

- [ ] Upload a **publicly visible YouTube** video and add its URL to Devpost.
- [ ] Keep it under **three minutes**; include clear audio.
- [ ] Show what was built and how Codex and verified GPT-5.6 usage contributed.
- [ ] Show the safety disclaimer, local model staging, review workflow, and
  confirmed-only GeoJSON export.
- [ ] State that RT-DETR-R18 is a generic COCO baseline, not a validated
  ordnance model; do not claim held-out ordnance metrics.
- [ ] Use only media, music, logos, and trademarks that the entrant is allowed
  to use. Prefer original narration and screen recordings.

## Final gate

- [ ] Add a thumbnail (the current Devpost draft uses the placeholder).
- [ ] Re-check the public video URL, public visibility, sub-three-minute
  duration, and voiceover coverage of the project, Codex, and GPT-5.6.
- [ ] Re-check the `/feedback` session ID, repository access, README setup
  instructions, category, and teammate status on Devpost's Final reminder.
- [ ] Read and accept the Official Rules and Devpost Terms of Service checkbox
  only when the entrant is ready to submit.
- [ ] Submit before **July 21, 2026, 5:00 pm PDT**.
- [ ] Re-read the live official rules immediately before submission; Devpost
  controls if the page and this checklist differ.
